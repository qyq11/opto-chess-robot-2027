# 智能车光电象棋对抗：研究摘要

核查日期：2026-10-13。以下区分**一手研究结论**与**针对本赛题的设计判断**；方案必须以官方规则及后续答疑为准。现有 STM32 可保留，Linux 板承担视觉和决策。

## 建议路线

| 路线 | 主要实现 | 适用判断与代价 |
|---|---|---|
| **A．差速车 + 双尺度视觉，主线** | 两驱编码器 + IMU；车载广角巡扫找棋子/对手，近场相机读字及推送；浅 V/U 形柔性导向推板；状态机 + 在线目标排序 + 短时避障 | **设计判断：优先完成。** 结构轻、牵引力好，能把精力用于识别、连续得分和故障恢复；侧向修正需要退出重对准，勿带棋子急转。 |
| **B．全向车 + 视觉/接触反馈，进阶** | 三轮全向或四轮麦轮；保持推板朝向时横移修正；小型压力/弹片传感器检测丢棋、受阻；局部 MPPI/MPC | **设计判断：用于确实受对准耗时限制时。** 接触控制可借鉴 Force Push [3]，但原系统的力传感器和定位条件不能直接移植；打滑、推力、重量和轮速标定比 A 更难。 |
| **C．开放滚轮导流 + 成组推送，备选** | 差速底盘；开放导流推板与低速滚轮；识别可共同送门的小棋群，规划成组推送 | **设计判断：做吞吐率对照实验。** 有望减少往返，但易卡塞、遮挡和丢棋；须先确认多枚计分规则，保持机构开放可退出。现有参考未证明该机构在本赛题优于单枚推送。 |

**不因预算充足先增加机构。** A 的关键能力完成后，再凭真实完整任务耗时决定升级 B 或 C；三条路线不是三个必须同时制作的整车。用户确认 SLAM 后，主文新增 **D：SLAM + 3D 场景 + 自主导航**，可叠加 A/B；定位、建图、规划及仿真的分工与 RoboMaster 适配边界见[SLAM 补充比较](SLAM_补充比较.md)。

**学习策略是通用后期模块，不是方案 C 的名称。** 在可靠整机上自建规则仿真，先人工策略/模仿学习，再尝试 PPO 或 SAC；学习选目标、放弃时机或推送微调，保留确定性控制回退。VPG [6] 支持研究视觉动作价值，但原任务不是小车对抗；真实得分对照实验通过后再部署。

## 智能化应落在这些闭环上

- **认棋：** 远场只把圆盘、颜色作为候选；高分目标靠近后读字。OpenCV 轮廓/椭圆与颜色分割 + 透视校正，再用 MobileNetV3-Small 对棋子裁剪图分类 [1–2]；在实际棋子上采集旋转、斜视、反光、遮挡样本，加入“未知”，按拍摄场次/棋子实物划分验证集。预训练 ImageNet 模型不能直接识别象棋字。
- **定位：** ≤180 mm 高度的车载相机不能被当作俯视全场相机；使用巡扫局部图、编码器/IMU与可见场边/门口几何校正。平面单应仅适用于对应平面 [1]：棋子顶面有高度，须单独建模或标定，不能把地面单应直接用于顶面中心。遮挡或定位不确定时减速、重观测。
- **推送：** 从“棋子→己方门”的反向侧接近，先确认再低速接触；控制棋子中心到输送线的横向误差，同时限制转弯曲率。导向推板仅作地面推送，开口、释放、擦墙脱困需实测；多接触稳定推送理论 [4] 支持研究这个方向，**不等于任意 V 形推板必然稳定**。电机电流适合受阻检测，不能直接替代二维接触力矢量 [3]。
- **决策：** 建议 `收益 = E[规则净得分 | 观测] × P(完整输送成功) / (巡看 + 接近 + 对准 + 推送 + 入门确认耗时) − 风险惩罚`。身份置信度已进入期望净得分；逐目标统计完整耗时和成功率。对手轨迹用短时速度估计和不确定区间；不追逐远处高分子，不为保留目标而冲撞。
- **避障：** 未选棋子、对手和场边是障碍；接触阶段只为当前目标设接触许可，并检查“车体 + 推送棋子”共同占据区域。Nav2 MPPI 可借鉴短时采样和轨迹代价 [7]，需要自己处理推送接触、对手预测与目标切换，不能把标准导航栈当完整比赛策略。
- **验收：** 统计身份错判、丢棋、误入门、受阻恢复、完整得分周期、每局净分/失败原因；使用相同布局和对手进行 A/B 对比。学习模块只有在真实场连续对抗提高有效得分且不增加故障时才上车。国赛一、二等奖是研发目标，资料不能保证获奖。
