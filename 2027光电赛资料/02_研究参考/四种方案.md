# 智能车光电象棋对抗：四种方案

整理日期：2026-10-13。本文统一收录 A、B、C、D 四种方案的比较、实现要点、研究依据和验收方法。以下区分**一手研究结论**与**针对本赛题的设计判断**；方案必须以官方规则及后续答疑为准，尚无本车实测性能。现有 STM32 可保留，Linux 板承担视觉和决策；规则、整机配置与开发节奏见[整机方案](../方案_智能车光电象棋对抗.md)。

## 四种方案总览

| 方案 | 主要实现 | 预期收益 | 难点与选用条件 |
|---|---|---|---|
| **A．差速车 + 双尺度视觉，主线** | 两驱编码器 + IMU；广角巡扫找棋子/对手，近场相机读字及推送；开放浅 V/U 形柔性导向推板；状态机 + 在线目标排序 + 短时避障 | 结构轻、牵引力好，便于先完成识别、连续得分和故障恢复 | **优先完成稳定原型。** 侧向修正需要退出重对准，勿带棋子急转 |
| **B．全向车 + 视觉/接触反馈，进阶** | 三轮全向或四轮麦轮；保持推板朝向时横移修正；小型压力/弹片传感器；局部 MPPI/MPC | 有望缩短对准时间，让侧向调整与解堵更灵活 | 对准耗时确实限制得分时验证；打滑、推力、重量与轮速标定比 A 更难，Force Push 的原定位/力传感条件不能直接移植 |
| **C．开放滚轮导流 + 成组推送，备选** | 差速底盘；开放导流推板与低速滚轮；识别可共同送门的小棋群，规划成组推送 | 有望减少往返，提高单位时间得分 | 先确认多枚计分规则；易卡塞、遮挡和丢棋，须做吞吐率对照实验；现有参考未证明其在本赛题优于单枚推送 |
| **D．SLAM + 3D 场景 + 自主导航，进阶** | 在 A/B 上增加同步双目/IMU、回环与重定位；3D 地图投影为二维/2.5D 任务地图；导航到预推位，保留近场推送闭环 | 特征足够时有望减小长期漂移，改善失定位恢复，并复用地图与仿真测试 | 定位确实限制得分时验证；弱纹理、运动模糊、动态干扰，以及标定、算力、功耗和重量均需实测 |

**不因预算充足先增加机构。** 先完成 A 的稳定得分闭环，再凭真实完整任务耗时决定是否采用 B、C 或 D。四种方案用于比较和选型，不要求同时制作四辆整车；D 是定位增强路线，可与 A/B 组合。3D 仿真可以先做，完整车载 3D SLAM 是否采用由实测决定。

## 方案 A：差速车 + 双尺度视觉

**实现要点：** 两驱差速底盘配编码器和 IMU；车载广角相机巡扫圆盘、颜色和对手，近场相机确认字样与推送偏差。开放浅 V/U 形柔性导向推板用于地面推送，状态机组织巡扫、确认、接近、对准、推送、入门复核和失败恢复。

**定位与控制：** 使用轮速/IMU、已知发车姿态和场边/门框几何校正，维护巡扫局部地图。先绕到“棋子→己方门”的反向侧，再低速接触；限制推送曲率。A 的两个相机承担不同视角任务，不能直接作为标定双目使用。

**取舍与验证：** 结构、重量与牵引力较容易调试，适合优先完成稳定原型；绕行和退出重对准会增加耗时。以单枚完整得分周期、身份错判、丢棋及受阻恢复作为基线，供 B/C/D 比较。

## 方案 B：全向车 + 视觉/接触反馈

**实现要点：** 三轮全向或四轮麦轮底盘，在保持推板朝向时横移修正；视觉与小型压力/弹片接触检测融合，判断丢棋和受阻，再评估局部 MPPI/MPC 控制。

**研究依据：** Force Push [3] 展示了全向移动机器人用力反馈沿路径推送的方法，但原系统依赖接触点定位、初始物体位置与力矩传感器，不能直接套到本车。小型接触传感适合检测接触状态；电机电流适合受阻检测，不能直接替代二维接触力矢量。

**取舍与验证：** 当 A 的对准时间确实限制得分时做对照。重点测横移纠偏收益、轮滑移、实际推力、轮速标定和整车重量；只有完整得分率超过 A 才考虑替换底盘。

## 方案 C：开放滚轮导流 + 成组推送

**实现要点：** 差速底盘配开放导流推板与低速滚轮；识别可共同送门的小棋群，按棋群价值和完整输送用时规划成组推送，机构保持开放且能退出重试。

**研究边界：** 多接触稳定推送理论 [4] 可支持机构和稳定方向研究，但不等于任意 V 形推板必然稳定；圆棋子、高速推送和滚轮导流仍须实测。现有参考没有证明该机构在本赛题优于单枚推送。

**取舍与验证：** 先确认多枚同时进门的计分规则，再比较同一布局下的吞吐率。重点记录卡塞、遮挡读字、丢棋与高分棋损失；完整周期的实际收益超过单枚基线后再采用。

## 方案 D：SLAM + 3D 场景 + 自主导航

**实现要点：** SLAM（Simultaneous Localization and Mapping，同时定位与建图）承担定位与地图估计，导航器承担路径规划，3D 仿真工具承担虚拟车和场地搭建。D 主要增强定位，认棋、目标排序、接触推送与失败恢复仍需各自实现。

**建议链路：** 将巡扫相机升级为同步双目，保留近场相机 → RTAB-Map 验证米制 3D 地图/重定位，或 ORB-SLAM3 比较视觉惯性位姿估计 → 二维动态代价地图/Nav2 → 棋子背后的预推位 → 专用推送控制器。静态地图只保留固定场景，棋子/对手另做动态跟踪；回环位姿修正后重新规划。已有局部地图、路径规划或离线仿真并不代表已经采用完整 SLAM。

**部署边界：** 3D 仿真和算法对照可在电脑完成，正式比赛仍由车载计算自主运行。新增系统须提高得分率或失定位恢复能力，并满足整车尺寸与 1.5 kg 限重。

### 模块分工

| 模块 | 负责什么 | 本车的实现建议 |
|---|---|---|
| SLAM / 重定位 | 根据相机/IMU等估计车位姿、建立地图；部分系统能回环纠漂、丢失后重新定位 | 先验证同步双目视觉；相机、IMU、编码器需标定和时间同步 |
| 导航 / 路径规划 | 把位姿、目标和障碍转为可执行路线与速度 | 静态场地 + 动态棋子/对手；到棋子背后预推位，再交给推送控制器 |
| 3D 仿真 | 在电脑搭建虚拟车、场地、棋子，验证传感器、碰撞、策略 | Gazebo 先做工程仿真；具备合适 GPU 时再评估 Isaac Sim/训练工具 |

这些模块组成感知—规划—行动闭环；学习和具身大模型可另行加入，不是采用 SLAM 的前提。

### 定位能力与 A 的比较

| 维度 | A：轮速/IMU + 视觉几何 + 局部地图 | D：SLAM + 地图导航 |
|---|---|---|
| 主要收益 | 直接利用小场地、已知发车和门框几何；开发链路短 | 在特征足够时，有望改善长期漂移、回环与重新定位 |
| 主要风险 | 轮滑移和遮挡导致漂移，依赖可靠几何观测 | 弱纹理、运动模糊、动态目标及重复外观影响跟踪/回环；需实测 |
| 硬件/计算 | 原广角与近场相机、STM32 + Linux | 同步双目或 RGB-D/视觉惯性配置，可能增加计算、功耗与重量 |
| 任务能力 | 已含认棋、对手跟踪、选目标、推送 | SLAM 主要增强定位；仍需原任务识别、目标排序、接触推送与失败恢复 |
| 建议 | 稳定得分基线 | 可叠加 A/B；定位确实限制得分时再部署 |

**推荐：3D 仿真先做，车载采用二维/2.5D 任务地图；完整 3D SLAM 做对照实验。** 3D 地图保存空间几何，可投影到地面做导航；不要把稀疏特征点地图当完整障碍地图。棋子顶面高度需要补偿，棋子/对手的动态位置不能长期写成静态地图。对目标棋子的接触许可仅在推送状态启用，同时检查“车体 + 被推棋子”的占据范围。

### 一手项目与边界

- **[RoboMaster：pb2025_sentry_nav](https://github.com/SMBU-PolarBear-Robotics-Team/pb2025_sentry_nav)**：原 README 明确 Mid360 + Point-LIO + small_gicp 重定位 + Nav2 + 全向跟踪器，支持仿真/实车；主仓 Apache-2.0，子模块另查。它是可参考的真实哨兵导航架构，尚未提供本赛题认棋/推送策略。激光功率/等级、质量、盲区和安装高度需重新核对。
- **[RTAB-Map](https://introlab.github.io/rtabmap/)**：RGB-D、双目和 LiDAR 图优化 SLAM，有回环检测及 3D 建图；适合先验证可视化地图/重定位。核心 BSD-3-Clause，依赖单独核查；[ROS 2 适配层](https://github.com/introlab/rtabmap_ros/tree/ros2)与 Nav2 集成还需配置坐标系、里程计和地图。RGB-D 主动光源也需核对本赛题规则；建议先试被动双目。
- **[ORB-SLAM3](https://github.com/UZ-SLAMLab/ORB_SLAM3)**：支持单目、双目、RGB-D、视觉惯性和多地图；适合对比视觉惯性位姿估计。原作者示例主要是较早 ROS/Ubuntu 环境，不是现成 ROS 2 比赛包；需适配，不能承诺树莓派实时性能。纯单目米制尺度与惯性初始化需专门处理，优先同步双目/IMU。核心 GPL-3.0，依赖另查。
- **[Nav2](https://docs.nav2.org/)**：负责导航规划/控制，与 SLAM 分工；接触推送时须切换到专用控制器，避免两个节点同时发底盘指令。[Gazebo](https://gazebosim.org/docs/latest/getstarted/)负责仿真场景；[Isaac Sim 官方硬件要求](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)应在选训练电脑前核对。仿真摩擦、轮滑移、低棋子接触和相机视角都要按实测标定。

**小场地特有问题（设计推断）：** 80 mm 围挡、低矮棋子和均匀地面，对雷达高度过滤与视觉特征都不友好；车载相机还可能看到场外观众等动态背景。正式场不默认允许人为增加标签/纹理或使用外置相机。RoboMaster 大车参数不能原样复用。

例如该哨兵包的[原实车参数](https://github.com/SMBU-PolarBear-Robotics-Team/pb2025_sentry_nav/blob/main/pb2025_nav_bringup/config/reality/nav2_params.yaml)采用 0.5 m 近距盲区过滤、0.15 m 到点容差及 0.1 m 障碍最低高度过滤（其 terrain 点云 intensity 被定义为离地高度）。**据此推断**，80 mm 围挡可能被默认过滤掉；这些参数及全向控制器、碰撞外形都必须为本车重新设定和实测。

### 验收与选用条件

1. 用 A 记录真实图像、IMU、轮速和完整得分失败原因；如计划双目，另采同步双目数据，原 A 两个不同视角相机不能直接拼成双目。
2. 先在电脑比较 RTAB-Map 与 ORB-SLAM3 的跟踪保持、定位误差、重定位耗时；利用自建训练场独立真值测量，不把算法自己的轨迹当真值。
3. 在相同棋局、灯光、对手和比赛时长下比较 A 与 A+D 的得分/分钟、胜率、失定位恢复、延迟和温升。证明收益后再搬到车载 Linux，满足尺寸/限重并保留故障停车。

## 四种方案共用的智能化闭环

- **认棋：** 远场只把圆盘、颜色作为候选；高分目标靠近后读字。OpenCV 轮廓/椭圆与颜色分割 + 透视校正，再用 MobileNetV3-Small 对棋子裁剪图分类 [1–2]；在实际棋子上采集旋转、斜视、反光、遮挡样本，加入“未知”，按拍摄场次/棋子实物划分验证集。预训练 ImageNet 模型不能直接识别象棋字。
- **定位：** A/B/C 可采用轮速/IMU与视觉几何基线，D 再引入 SLAM 增强。≤180 mm 高度的车载相机不能被当作俯视全场相机；使用巡扫局部图、编码器/IMU与可见场边/门口几何校正。平面单应仅适用于对应平面 [1]：棋子顶面有高度，须单独建模或标定，不能把地面单应直接用于顶面中心。遮挡或定位不确定时减速、重观测。
- **推送：** 从“棋子→己方门”的反向侧接近，先确认再低速接触；控制棋子中心到输送线的横向误差，同时限制转弯曲率。导向推板仅作地面推送，开口、释放、擦墙脱困需实测；多接触稳定推送理论 [4] 支持研究这个方向，**不等于任意 V 形推板必然稳定**。电机电流适合受阻检测，不能直接替代二维接触力矢量 [3]。
- **决策：** 建议 `收益 = E[规则净得分 | 观测] × P(完整输送成功) / (巡看 + 接近 + 对准 + 推送 + 入门确认耗时) − 风险惩罚`。身份置信度已进入期望净得分；逐目标统计完整耗时和成功率。对手轨迹用短时速度估计和不确定区间；不追逐远处高分子，不为保留目标而冲撞。
- **避障：** 未选棋子、对手和场边是障碍；接触阶段只为当前目标设接触许可，并检查“车体 + 推送棋子”共同占据区域。Nav2 MPPI 可借鉴短时采样和轨迹代价 [7]，需要自己处理推送接触、对手预测与目标切换，不能把标准导航栈当完整比赛策略。
- **验收：** 统计身份错判、丢棋、误入门、受阻恢复、完整得分周期、每局净分/失败原因；使用相同布局和对手进行 A/B 对比。学习模块只有在真实场连续对抗提高有效得分且不增加故障时才上车。国赛一、二等奖是研发目标，资料不能保证获奖。

## 通用后期模块：学习策略

**学习策略是通用后期模块，不是方案 C 的名称，也不是采用 SLAM 的前提。** 在可靠整机上自建规则仿真，先人工策略/模仿学习，再尝试 PPO 或 SAC；学习选目标、放弃时机或推送微调，保留确定性控制回退。VPG [6] 支持研究视觉动作价值，但原任务不是小车对抗；真实得分对照实验通过后再部署。具身大模型可另行评估，不影响四种方案的基本闭环分工。
