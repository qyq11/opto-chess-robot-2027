# 底盘串口接线与首轮测试

更新：2026-10-30。适用方案：泰山派3M RK3576通过40针排针的硬件串口，直接控制亚博四路编码器电机驱动；本轮不加STM32。按用户最新要求，先增加电脑经USB串口助手的台架调试，再做RK40针串口接线验收；两者的结果分别登记。

本文是本车直连驱动的接线、厂家命令用法与验收边界的统一入口。驱动线上使用厂家原协议，项目不另外增加帧头、序号或校验字段。任务勾选只在[开发计划](../01_plans/01_开发计划.md)维护；本文保存操作流程，实际结果统一见[底盘串口记录](../03_records/04_20261030_底盘串口调试.md)。用户已报告四轮、电机装好；电脑USB配置查询已收到真实回复，最新用户已观察到M3转动、感觉速度很慢。实际轮速、停车、反转及RK串口尚未验收，未编译RK控制程序。

### 软件与串口设置

当前实际测试电机按此前确认接驱动板M3（第3路），最新用户已报告驱动板与稳压板通电。先前仅USB供电时电压回复3.9V，不作为本次动力供电结果。下列电脑单轮流程已按M3调整；后面的RK四轮流程仍按M1–M4逐路验收。

厂家[UartAssist 5.0.3原件](../../03_hardware/01_机械/01_厂家资料/03_四路电机驱动/13_UartAssist_5.0.3.exe)及[电脑调试教程](../../03_hardware/01_机械/01_厂家资料/03_四路电机驱动/14_PC串口调试.pdf)已提取到正式资料目录。为把运行设置留在临时目录，调试时使用项目`temp/motor-uart/`里的软件副本。电脑通过USB数据线直接接驱动板Type-C口，不需要另外接USB转TTL小板；此阶段不接RK的TX/RX。

先在Windows设备管理器查看“端口（COM和LPT）”，比较插入/拔出这块板时新增/消失的串口。蓝牙串口不能作为电机驱动串口；若没有新增设备，先换确认能传数据的线、直连电脑USB口。若新增的是未知设备，按其硬件标识确认芯片和匹配驱动，不凭猜测安装。

串口助手左上角选择已确认的COM口，设置115200波特、数据位8、校验位NONE、停止位1、流控NONE。接收和发送均选ASCII（文本），不要选HEX（十六进制）；取消“自动发送附加位”“循环周期”，保留命令中的英文符号。点击“打开”后按钮应变成“关闭”，这只证明端口已打开，还要核对真实回包。不要用软件窗口关闭来代替电机停车。

### 断电后连接单台电机，当前用M3

先拔掉USB，保持电池未接。电机固定牢、轮子悬空，驱动板垫绝缘材料；碳纤维板导电，不能让焊点直接贴底板。先接一台310，其余三路空着。

若使用厂家原配PH2.0六针双头线，按厂家说明黑色端接310电机，白色端接驱动板编码器电机接口，并核实际插壳、锁扣和丝印；不强插反向插头。若电机端是六针插头、驱动端是六个分散杜邦头，按下表接驱动第3组IO插座，不凭线颜色或照片左右猜针序。

| 电机丝印 | 驱动板第3组信号 | 用途 |
| --- | --- | --- |
| M1 | 第3路动力M+ | 电机动力正端 |
| M2 | 第3路动力M− | 电机动力负端 |
| V | 3V3 | 编码器供电 |
| G | GND | 编码器地 |
| A | H3A | 编码器A信号 |
| B | H3B | 编码器B信号 |

电机本体的M1/M2是两根动力线，驱动板的M1–M4是四个电机通道，含义不同。M+/M−必须属于同一第3组，H3A/H3B也属于这一组。若实物丝印、线束或接口与资料不同，先拍清板上接口和六根线再核对，不能按此表猜物理位置。依据[厂家电脑教程](https://www.yahboom.net/study/MD310/14019/)及[310接法](https://www.yahboom.net/study/MD310/14018/)；厂家表中以第1组为例，此处按同样功能对应到第3组。

动力电源用本车7.4V/2S电池，满充8.4V。电池正极经已核实的保险/开关接驱动动力输入正极，负极接动力输入负极；按板上实际电源丝印核极性，不能接到辅助5V/3V3口。USB不作为电机动力电源。接电池前检查无裸铜相碰、轮子已架空、随手能切断动力。电源和线束未核实时先停在USB识别步骤。

### 动力是否需要经过稳压板

本车2S电池接电机驱动的动力支路，不经过5V稳压板；稳压板只在计算支路把电池电压降成5V给RK，接法见[系统规划第6.1节](./03_系统规划.md#61-电池降压板驱动到底怎么接)。当前只测电脑与电机，先核清动力支路，RK和稳压板暂不接入本次单轮测试。

| 部位标识 | 输入或输出 | 本车用途 |
| --- | --- | --- |
| 电池XT60主放电口 | 电池输出 | 经匹配取电线、保险/开关和分电接动力支路；不按插壳公母简称猜配对 |
| 驱动DC5V～12V的+／−端 | 驱动动力输入 | 接电池动力支路正负端，不接到电机M+/M−或辅助低压接口 |
| 稳压板IN+／IN−、DC6～24V-IN | 稳压板输入 | 接电池计算支路正负端 |
| 稳压板DC5V-OUT、Type-C输出 | 稳压板输出 | 给RK的Power Type-C供电 |

采购登记的电池是XT60，驱动附带线是T插到红黑裸线，两者不能直接对插。现有正式方案使用XT60取电及绝缘分电，不默认新增XT60转T插。实际是否缺线要按现物核对，不把裸线临时塞进电池插头，也不用小平衡插头承载电机电流。接电前先把软件发送框中的非零速度改成零PWM并发送，再关串口、拔USB；没有电源端子和线束实物依据时，先核照片而不按商品图位置猜正负。

2026-10-30已按用户指定京东链接核对[对应规格电池图](../../05_data/01_raw/04_hardware/20261030_battery_reference_01.jpg)：黄色XT60插孔端是主放电口，应使用配对的金属插针端成品取电线；白色小插头用于平衡检测和充电辅助，不接驱动动力。图和SKU核对过程见[同一调试记录](../03_records/04_20261030_底盘串口调试.md#按用户指定商品页核对电池插头)。在电池和USB断开时，动力支路红线经保险/开关接驱动DC5V～12V输入“+”，黑线接输入“−”，按实际丝印核极性。压好端头后插入夹线孔、拧紧并轻拉检查，最后才对插电池；现有取电线、保护件未确认配齐时不安排上电。

原配T插电源线并非不能使用：剥开的红黑线可接驱动动力端子，只是红色T插不能直接插黄色XT60。电脑单轮台架若保留原配线，可配XT60金属插针端至T插金属插孔端成品转接头，常见名称“XT60公转T插母”；按两端触点和极性核对，不能买反向版本。[厂家同方向产品](https://genstattu.com/xt60-male-to-deans-t-female-adapter/)仅作类型参考，未在本车实测。保险/开关仍需落实；正式整车分电主线保持原定义，不因临时台架配接增加一套重复采购。

### 先查询，再配置，最后短时转轮

以下每个代码块是要填入串口助手“数据发送”框的一条文本，只点击一次“发送”，不加引号。先按上述方式确认端口、接线和供电，保持零输出：

```text
$pwm:0,0,0,0#
```

查询配置，应收到包含电机类型、线数、减速比、轮径等字段的实际返回；只看到发送栏回显不算通信通过。

```text
$read_flash#
```

查询电压，应收到`$Battery:实际电压V#`形式的帧，并与电源测量核对。只接USB时查询是否回复取决于实际板卡供电设计；没有回复时不能立即判断为软件故障，也不要发送转动命令。

```text
$read_vol#
```

收到有效回包后，逐条配置，每条等待实际确认再继续。按本车310编码器A→A、B→B、13线、1:20、65mm轮设置；不能照抄厂家48mm轮径，也不改PID或恢复出厂。

```text
$mtype:2#
```

```text
$mline:13#
```

```text
$mphase:20#
```

```text
$wdiameter:65#
```

```text
$read_flash#
```

确认返回类型2、13线、减速比20、轮径65。保持零PWM，开启编码器总计数及轮速反馈，再手动慢转轮子，核对只有第3通道变化。

```text
$upload:1,0,1#
```

回包应含`$MAll:…#`和`$MSPD:…#`。手动转轮后放开，确定动力停机手段可用，再用下列命令测试第3路低速。提前把下面的停止命令加入软件“快捷指令”，确认如何单击发送；低速运行约0.5秒后立即发送零速度。若不能可靠完成短时动作和停止，先不要发送启动命令。这里的持续时间由操作者控制，速度命令本身没有持续时间字段。

速度单位为mm/s（毫米每秒），依据[厂家串口示例](https://www.yahboom.net/study/MD310/14033/)及归档STM32示例`USER/main.c`第3～4行。第三项50表示M3目标轮缘线速度50mm/s，即5cm/s；按65mm轮径计算约14.7转/分钟、4.08秒一圈，所以本轮目标本身很低。`$MSPD`第三项是驱动计算的M3实际轮速，应结合编码器配置与实物转动核对；计算值不作为实测结果，也不能直接当作麦轮整车行驶速度。

```text
$spd:0,0,50,0#
```

```text
$spd:0,0,0,0#
```

核实际转轮、原始反馈和停车；速度指令不返回OK，不能因没OK重复加速。反转同样短时执行，随后再次发送上面的零速度。

```text
$spd:0,0,-50,0#
```

结束前使用零PWM关闭主动输出，再按实际板卡供电说明关电；接拆电机线必须使USB与电池都断开。

```text
$pwm:0,0,0,0#
```

零速度仍有主动调速，不能在此模式用手强拧。断USB或关闭软件可能保留最后速度，失联停车需要另测。电脑测试只确认所测电机、驱动和USB通信，不代表RK40针串口、四轮整车或异常停车已通过。实测开始后，真实收发、接线照片和动作证据统一追加到底盘串口记录；没有真实结果前不创建完成记录。

## 1. 首轮要证明什么

先不接摄像头：RK能查询驱动配置和电压、收到四轮编码器/轮速；逐轮短时低速正转、反转并停车，驱动口、实物轮子和反馈通道一一对应。首轮先用下面的Bash手动联调，正式运动服务后续用C实现。轮速闭环由驱动板负责，RK负责整车速度换算、限速、动作有效期和反馈管理。

正常停车与失联停车分开验收。RK程序仍能发出停止命令，不证明RK卡死、串口断线或驱动失电时也能停车。

## 2. 上电前的接线核对

### 2.1 先确认RK针脚，再接信号线

归档[泰山派规格书](../../04_references/04_datasheets/01_泰山派3M_RK3576_规格书.pdf)第8页给出以下**资料候选**。第1页图示板丝印V1.3，但尚未确认与本车实物相同。2026-10-30访问[官方40针说明](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/hardware-gpio/taishanpi-3m/v1-0.html)时，正文没有可读针表，不能用该网页补齐实物确认。

| 信号 | 规格书候选物理针号 | 规格书功能名 | 本车状态 |
| --- | --- | --- | --- |
| RK发送TX | 8 | UART4_TX_M0 / GPIO2_D0 | 候选，待实物版本、原理图与镜像核对 |
| RK接收RX | 10 | UART4_RX_M0 / GPIO2_D1 | 候选，须与TX属于同一路硬件UART |
| 信号地 | 6 | GND | 待按实物针1方向核对；其他GND脚也须有明确依据 |

**此表不能直接当作已批准上电的针位。** 物理针号是排针位置，GPIO名称是芯片信号，两者不能混用；UART4也不自动等于Linux的某个固定设备名。按本车版本原理图、排针方向和镜像配置填齐以下信息，再接TX/RX：

| 必须确认的事项 | 需保存的依据 | 当前状态 |
| --- | --- | --- |
| RK板版本、针1位置、TX/RX/GND物理位置 | 实物正反面照片、对应原理图版本 | 待核 |
| RK与驱动串口的逻辑电压及允许输入范围 | 双方规格；必要时测空闲电平/波形，测量不能替代耐压规格 | 待核；不假定40针全部为3.3V |
| UART复用、驱动和实际设备节点 | 镜像/内核版本、已启用配置、实际节点与引脚映射 | 待核；不预填`/dev/ttyS4` |
| 该口不用于系统登录/启动日志 | 内核命令行、登录服务和串口占用检查 | 待核；启动日志不能混入电机命令 |
| 一侧掉电时不会经TX/RX反向供电 | 器件断电容忍规格或支持断电隔离的转换器件及验证 | 待核；仅拔掉5V线不能证明无反灌 |

两端电平不兼容时，增加匹配UART方向及速率的电平转换；不向未知RK信号脚送5V。驱动失电条件未落实前，先用确认支持断电隔离的接口；没有该条件时，在双方都断电时接拆信号，并采用双方一起上下电的台架步骤，暂不进行带信号的独立动力掉电试验。

### 2.2 信号与电源怎么接

| 连接 | 接法 | 核对重点 |
| --- | --- | --- |
| RK40针硬件UART → 驱动 | RK TX→驱动RX2，RK RX←驱动TX2，GND↔GND | 三芯短线，按功能交叉；针位/电平核实后才接 |
| 驱动串口插头5V线 | 悬空、单独绝缘 | RK与驱动各自供电，不把两板5V相连 |
| 动力 | 已购2S电池经保险/开关、分电、F1/S1接驱动输入正负端 | 满充8.4V；核实际极性、端子及保护，电机电流不经过RK排针 |
| RK | 计算支路稳压5V，经合适Type-C线接Power口 | 不用驱动辅助5V给RK供电；Type-C与排针不同时供电 |
| 共地 | 两支路在分电处共享负参考，UART再接短信号GND | 电机大电流负线直接回分电，不沿细串口GND回流 |
| 固定 | RK和驱动用绝缘支柱，线束固定 | 碳纤维导电；四轮架空固定，不手持运行 |

完整供电与线束见[系统规划第6节](./03_系统规划.md#6-整车供电图与电源安排)。先确认随手可切断动力；测试中的“发送停止”不能替代实际观察轮子停止。

### 2.3 电机、编码器与轮序

以确定的车头为前，从车自身看左右。四路驱动M1=左前、M2=左后、M3=右前、M4=右后；先贴标签，再按实物逐轮确认。电机本体的M1/M2是两根动力线，与驱动组号M1–M4含义不同。

| 310电机端 | 驱动第n组端 | 说明 |
| --- | --- | --- |
| M1 / M2 | Mn+ / Mn− | 该轮动力线 |
| V / G | 3V3 / GND | 编码器电源与地，按实际丝印及厂家配线核对 |
| A / B | HnA / HnB | 本方案采用310的A→A、B→B接法 |

每台使用原配六芯线；不能凭颜色或照片左右顺序判断插壳。四组编码器只接驱动板。接法依据[厂家310说明](https://www.yahboom.net/study/MD310/14018/)，实际正方向通过下面的单轮测试登记，不假定四路正数都让整车前进。

## 4. 建立可核对的发送与接收窗口

以下适用于具备Bash、GNU串口工具与串口访问权限的RK Linux。权限不足时按镜像说明配置串口用户组或在获授权的管理员终端执行，不把设备权限改成所有人可写。Buildroot若缺少工具，应先核工具选项或改用后续C测试程序，不能把下面命令成功退出视为通信通过。

在RK项目目录打开两个终端A、B；两个终端都先设置同一个已核对端口。**必须先将占位内容替换为实际节点**，不以规格书的UART编号猜节点。

```bash
export MOTOR_PORT='/dev/已核对的实际串口节点'
```

```bash
test -c "$MOTOR_PORT"
```

```bash
fuser -v "$MOTOR_PORT"
```

```bash
systemctl status "serial-getty@${MOTOR_PORT##*/}.service" --no-pager
```

没有systemd的镜像用对应登录管理方式核对；发现该口用于登录/其他程序时，先处理占用并保存改动，不与其同时打开。接收端只保留一个读者，防止两个程序分走回包。

两个终端都设置本轮日志目录；不同轮测试改目录名，不覆盖旧日志。

```bash
export MOTOR_LOG_DIR='temp/motor_uart/first_run'
```

```bash
mkdir -p "$MOTOR_LOG_DIR"
```

在终端A配置串口。`115200/8N1`表示115200波特、8数据位、无校验、1停止位；同时关闭硬件/软件流控及本地回显。

```bash
stty -F "$MOTOR_PORT" 115200 raw -echo -ixon -ixoff -crtscts cs8 -parenb -cstopb min 1 time 0
```

在终端A持续显示并保存驱动→RK的原始字节。回包可能连续排列，以`#`分帧；日志保留原样，不补写成看起来成功的回复。Ctrl+C只停止接收窗口，不代表电机停止。

```bash
stdbuf -o0 cat "$MOTOR_PORT" | tee -a "$MOTOR_LOG_DIR/rx_raw.log"
```

在终端B整体复制以下**Bash函数定义**，用于显示本地时间、串口、方向、编号和实际发送字符串。编号只写在日志，不发送给驱动；函数内部命令共同完成一次发送。

```bash
motor_send() {
  test -c "$MOTOR_PORT" || { printf '串口节点未核实或不存在\n' >&2; return 1; }
  MOTOR_SEQ=$(( ${MOTOR_SEQ:-0} + 1 ))
  printf '[%s] RK(%s) -> 驱动 [%s-%s] %s\n' "$(date '+%Y-%m-%dT%H:%M:%S%z')" "$MOTOR_PORT" "$BASHPID" "$MOTOR_SEQ" "$1" | tee -a "$MOTOR_LOG_DIR/tx.log"
  printf '%s' "$1" > "$MOTOR_PORT"
}
```

命令字符串必须用单引号包住，避免Bash把`$`开头内容当变量。只发送厂家帧本身，不附加本地序号；函数打印的TX是发送尝试，配置回包、编码器变化和实物动作才是执行依据。

## 5. 按顺序做首轮测试

### 5.1 保持零输出，先查参数

双方正确上电、车轮架空、停止操作已准备好后，先发送零PWM输出。

```bash
motor_send '$pwm:0,0,0,0#'
```

```bash
motor_send '$read_flash#'
```

```bash
motor_send '$read_vol#'
```

应看到驱动的实际配置查询回复和电压帧；手册电压格式示例为`$Battery:7.40V#`，这里的7.40只是格式示例，不是本车实测值。用万用表核对实际电源电压；没有有效回包时停留在供电/串口排查，不进入转轮测试。

### 5.2 设置310与65mm轮参数，再读回

每条单独发送，等待实际回复或驱动重启后稳定再执行下一条；不循环写入持久参数。

```bash
motor_send '$mtype:2#'
```

```bash
motor_send '$mline:13#'
```

```bash
motor_send '$mphase:20#'
```

```bash
motor_send '$wdiameter:65#'
```

```bash
motor_send '$read_flash#'
```

保存每条实际回复与最终配置全文，核对类型2、13线、1:20、轮径65mm。初轮沿用厂家PID，不发送PID修改、恢复出厂或固件烧写命令；改PID会引起重启，不能在运动时试改。

### 5.3 手动转轮核编码器

```bash
motor_send '$pwm:0,0,0,0#'
```

```bash
motor_send '$upload:1,0,1#'
```

应收到`$MAll:…#`总计数和`$MSPD:…#`轮速原始帧。逐个慢慢转动一个轮子，核对只有对应通道随之变化；记录正反方向。对轮胎作记号，转一整圈，比较起止总计数差；13×20×4=1040是四倍频口径下的名义计数/输出轴转，须核对当前固件实际口径。若幅值、符号或通道不符，先排查六芯线、编码器相位与配置。

只有零输出状态才做手动转轮；零速度模式仍在主动控制，不用手强拧运行中的轮子。上传开关通常不掉电保存，重上电后重新核对。

### 5.4 单轮短时正转、反转、停车

在终端B整体复制以下函数定义。一次调用发送速度、等待约0.5秒并尝试归零；Ctrl+C/TERM退出也尝试发送零速度。该机制依赖RK和串口仍工作，断电、SIGKILL、进程冻结或串口故障不能由它保证停车。

```bash
motor_pulse() (
  MOTOR_STOP_FRAME='$spd:0,0,0,0#'
  trap 'motor_send "$MOTOR_STOP_FRAME"' EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
  motor_send "$1" || exit 1
  sleep 0.5
)
```

先测左前M1。50是低速起点，厂家Linux例程将速度解释为轮周线速度mm/s；具体固件单位应与回传及一圈计数核对。低速不转或抖动时先检查原因，不直接大幅提高命令。

```bash
motor_pulse '$spd:50,0,0,0#'
```

```bash
motor_pulse '$spd:-50,0,0,0#'
```

随后逐轮执行，每次确认前一轮已停；四个值按M1、M2、M3、M4排列。

```bash
motor_pulse '$spd:0,50,0,0#'
```

```bash
motor_pulse '$spd:0,-50,0,0#'
```

```bash
motor_pulse '$spd:0,0,50,0#'
```

```bash
motor_pulse '$spd:0,0,-50,0#'
```

```bash
motor_pulse '$spd:0,0,0,50#'
```

```bash
motor_pulse '$spd:0,0,0,-50#'
```

每次保存发送与归零帧、对应原始反馈及轮子视频，登记实际位置、方向和停止表现；其他三轮应保持停止。速度命令按手册**不返回确认帧**，不能因没有OK而重复加大发送；也不能只凭写串口成功判定运动成功。

### 5.5 区分三种停止状态

零速度：驱动仍执行PID，主动维持零转速。

```bash
motor_send '$spd:0,0,0,0#'
```

零PWM：关闭主动输出；实际滑行/制动与阻力按板卡实测，不能把它称为机械刹车或保证立即停止。

```bash
motor_send '$pwm:0,0,0,0#'
```

第三种是通过已核实的动力停机开关切断驱动电源，验证前必须满足第2节的掉电接口条件。记录各状态停止耗时、反馈与实物现象；结束前先零输出，按已核实顺序关电。

## 6. 异常测试与落地条件

正常动作通过后，仍先架空。分别核对“应用不再产生新目标”“发送进程退出/冻结”“串口通信中断”“RK重新启动”“驱动重新上电”；记录最后有效命令、故障时刻、反馈是否中断、轮子多久停、是否重连后自行恢复。串口断线优先用可控的断线接口模拟，不在未知电平/掉电条件下带电拔接杜邦线。

手册没有明确承诺失联自动停车，不能假设重复发送速度就具备心跳。若驱动保持最后速度，应记录为未通过失联停车；在落地连续运行前落实经验证的驱动侧超时、硬件使能/停机回路或独立切断动力措施。人工S1可作为架空实验的停机手段，不能替代自主失联保护。同一RK上的独立进程、退出回调和看门狗也不能保证RK整机卡死时停车。

| 阶段 | 可以报告的完成范围 | 仍不能据此声称 |
| --- | --- | --- |
| 资料/流程整理 | 针位候选、供电关系、厂家命令与测试顺序已整理 | 本车针脚已确认、硬件已接通 |
| 查询与回包 | 保存真实配置/电压/编码器帧，方向和通道可核对 | 电机闭环或整车移动通过 |
| 四轮架空 | 四路低速正反转、零速度/零PWM有真实反馈与视频 | 地面距离准确、带载可靠或失联停车通过 |
| 异常保护 | 各故障下的实测停车与重连禁用有证据 | 尚未覆盖的故障也安全 |
| 落地与视觉 | 保护、供电和固定就绪后，再测前后/横移/旋转及视觉并行 | 仅轮速稳定就能准确定位或自主推棋 |

实测开始后再在记录目录维护同一份底盘串口记录，追加准备、排查、复测和验收；原始接线照片、未改写的收发日志和视频分别保留，按项目目录归档。反馈目前是接收时刻，不等同驱动的实际采样时刻；没有厂家时间戳时，不把它当精确同步数据。
