# RK3576 主控方案

主控确认：2026-10-24；直连控制更新：2026-10-30。用户已确定采用**立创泰山派3M RK3576，4GB RAM + 64GB eMMC，完整开发板**，作为本车视觉、定位与任务决策主控。本文依据当前代码、任务分工和厂家公开资料定义开发边界与验收条件；主控和原配散热套件已购买、已付款，到货与本车板端实测待确认。系统主线见[整机方案](./01_整机方案.md)。

## 1. 已确认方案

泰山派3M负责相机采集、轻量目标检测、按需棋字识别、几何定位、任务状态机，以及整车到四轮的速度换算、限速和串口反馈管理。2026-10-30按用户决定撤下额外STM32，RK经40针硬件串口直连亚博四路驱动；编码器计数和轮速PID仍在驱动板内完成。用户已定新增1个JY901S九轴IMU，优先I²C接RK、串口备用，尚未购买和接入，首轮底盘测试不依赖它。后续二维定位、地图和连续推棋排在基础验证之后，先测现有视觉方案，三维重建及额外测距暂不实施。这套任务拆分具有可实施的开发路径，实际延迟、识别精度和稳定性按第4节验收。完整搭建及可行性评估见[系统规划](./03_系统规划.md)。

官方型号为[LCKFB-TSPI3M-RK3576-4G-64G（商品编号C54110287）](https://item.szlcsc.com/57330947.html)，商品名称为“立创·泰山派开发板3M 4G+64G版本”。4GB运行内存用于系统和应用工作集，64GB eMMC用于系统、程序与数据存储；存储容量不直接提高计算速度。原型按有界队列、按需识别和第4节的内存预算实现。

历史评估曾比较RK3566、RK3576与RK3588，并一度采用野火鲁班猫5 RK3588作为基线；2026-10-24用户最终改为上述泰山派3M 4GB/64GB。历史板卡的供电、GPIO针号和镜像配置不能沿用到当前主控，原有电脑算法研究仍保留。

立创提供[系统快速指南](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/system-usage/)、[资料下载中心](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/download-center.html)、[USB相机验证](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/system-development-compilation/opencv/usb-camera-verification.html)和[YOLO11部署教程](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/ai/yolo-11/detection-model.html)，覆盖系统启动、镜像、图像采集与NPU部署，可支撑本项目开发。教程是迁移与验证的入口，现有棋子模型仍需独立完成转换与精度对照。

高分辨率双目稠密深度、视觉惯性SLAM、多模型高帧率并行尚未纳入当前性能承诺。后续任务确需这些能力时，先补充算法与数据基线，再测计算、带宽、内存和散热余量。

## 2. 实际需要多少计算

当前仓库已有 OpenCV 单图透视变换和人工 ROI 的通用 OCR 示例，没有自动全图检测、完整车载程序或象棋走棋搜索。

| 工作 | 现状及计算特点 | 部署安排 |
| --- | --- | --- |
| 采集、去畸变、透视校正 | 主要是像素与几何运算 | CPU 先实现并计时，按需使用硬件图像处理 |
| 棋子检测/跟踪 | 目前尚未实现自动全图检测 | 轻量网络可转 NPU；几何检测和跟踪在 CPU 测量 |
| 字样/字色识别 | 当前每个 ROI 尝试 24 个候选；12 个 ROI 共 288 次 OCR，在既有 Windows 环境约 4.04 秒 | 作为离线基线保留；板端只对当前目标按需识别，比较轻量分类与 OCR |
| 定位、选目标、任务状态机 | 无走棋博弈搜索需求 | CPU 执行，不能拿 NPU TOPS 代替这部分预算 |
| 运动控制 | 驱动执行轮速闭环，RK决定整车运动 | RK换算四轮速度、独立收发与检查反馈；驱动断线/主控卡死停车单独验收 |
| 双目深度 | 仅为可能使用的相机能力，尚无深度算法基线 | 单独测视差/匹配负载；相机同步不会自动完成深度计算 |

已有 OCR 的时间来自[电脑研究记录](../03_records/02_20261023_象棋识别.md#5-运行与复核)，不是 RK 性能。当前主要瓶颈既包括重复推理，也包括图像质量与模型对棋子字体的适应性，单纯换更强主控不能修复识别错误。

## 3. 板卡资源与接口安排

| 资源 | 已核规格或使用安排 | 开发边界 |
| --- | --- | --- |
| CPU | RK3576，4×Cortex-A72 + 4×Cortex-A53 | 承担采集管理、前后处理、几何计算、决策与通信，按整链路计时 |
| NPU | 标称6TOPS INT8，带稀疏计算条件 | 用于兼容的轻量模型；峰值算力不能直接换算为相机帧率 |
| 内存与存储 | 4GB RAM + 64GB eMMC | 系统、驱动和DMA等也占用内存；按应用与系统总资源分别测量 |
| 已购相机 | IMX415、30针MIPI、100度M12镜头；计划首轮单路采集 | 主板与模组逐针定义、供电、排线方向及镜像驱动待核，尚未确认可直接连接 |
| RK与四路驱动 | 40针硬件串口直连RX2/TX2/GND；厂家115200/8N1 | 针位、电平、复用、Linux节点和调试口占用核对后再接线；不使用USB作为本轮验收通道 |
| 编码器与扩展传感器 | 四组编码器接驱动；IMU/触点等以后按需求接RK兼容接口 | 先验证直连轮速反馈；外设电平、供电、引脚复用及驱动逐项核对 |

规格依据：[RK3576官方简介PDF](https://www.rock-chips.com/uploads/pdf/2024.3.18/191/RK3576%20Brief%20Datasheet%20V1.2-20240311.pdf)、[泰山派3M官方商品页](https://item.szlcsc.com/57330947.html)及[官方40Pin说明入口](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/hardware-gpio/taishanpi-3m/v1-0.html)。归档规格书第8页给出UART4_M0候选针位；2026-10-30访问官方40Pin页面时正文没有可读针表，尚不能确认其与到货板一致。不能预设所有GPIO均为3.3V，也不把候选UART映射直接当作本车已确认接线；具体核对见[底盘串口接线与首轮测试](./05_底盘串口接线与测试.md)。接线前以实际版本原理图、排针定义和所用镜像的设备树交叉确认，不能沿用鲁班猫脚位。

## 4. 初始资源预算与通过条件

下表是**泰山派3M RK3576 4GB板卡的初始原型设计目标，全部待实测**。先以单路相机、轻量模型和有界缓存实施，再随车辆速度、视场和任务要求修订；双路相机需要单独验收。

| 项目 | 起始条件/目标 | 要保存的结果 |
| --- | --- | --- |
| 采集 | 首轮评估单路1280×720、30fps；相机、MIPI驱动与输出模式需支持 | 实际格式、分辨率/帧率、时间戳和丢帧；双目另做并行验收 |
| 检测 | 640×640 输入，至少 15Hz | 模型版本、前后处理及整链路耗时 |
| 几何位置 | 从采集时间戳到目标位置输出 P95≤100ms | 按阶段计时，检查队列积压 |
| 身份确认 | 对当前目标按需识别，起步 5Hz，确认延迟目标≤300ms | 正误、拒识、重观察次数及完整确认耗时 |
| 内存 | 应用工作集先按≤1.5GB预算，缓存和队列有界，为系统、驱动与采集保留余量 | 各进程RSS/PSS及峰值、系统实际可用内存、NPU/视频DMA与CMA占用、日志/存储增长；不得发生OOM或靠持续换页维持运行 |
| 并行稳定性 | 相机、识别、决策和 UART 同时运行至少 30 分钟 | CPU、NPU、温度、频率、延迟分位数和重连情况 |
| 驱动直连 | 通过40针串口发厂家命令、收到轮速/计数并验证停车 | 具体收发、轮序/方向、反馈间隔与最大中断时长；区分正常停车和通信中断后的行为 |

此前USB方案的带宽示例：双路720p30若均为YUYV（每像素2字节），原始数据为`2×1280×720×30×2≈110.6MB/s`，超过USB2单总线理论60MB/s。压缩格式、USB3及实际总线拓扑会改变可用带宽。已购IMX415为MIPI模组，不能套用这一USB带宽计算判断采集是否可用；其输出模式、驱动与实际采集链路需在RK验证。图像过小或过度压缩可能影响认字，需要用实际棋子检查。

通过方法是同一套数据与同一组运行条件下，检查采集、识别、决策和通信同时运行的延迟、精度及资源余量。未达到时先定位采集、前后处理、模型或队列瓶颈；只有在必要任务与优化边界明确后，才重新评估主控型号。

## 5. 模型与软件迁移

[瑞芯微 RKNN Model Zoo](https://github.com/airockchip/rknn_model_zoo)给出了PP-OCRv4的ONNX→RKNN和Linux C API路径；立创[YOLO11教程](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/ai/yolo-11/detection-model.html)给出了RK3576目标的模型转换与板端编译路径。仓库目前保存的是 **PP-OCRv6_rec_small.onnx**，不能直接用v4或YOLO的示例、性能数字证明v6已兼容。全部部署以RK3576为转换目标，并固定实际镜像、驱动与运行库版本进行验证。

需要依次核对算子、固定输入形状、RKNN转换、运行库/驱动版本，再用相同输入对照原模型与板端结果；量化时检查逐类精度和拒识变化。记录模型来源、版本、哈希、转换参数、量化数据集与板端环境，使原模型和转换模型的结果可以复核。现有Python代码仍用于电脑上的数据研究，板端程序优先C、使用GCC；模型转换工具在受支持的电脑环境使用。

## 6. 采购落实

2026-10-24用户已购买并付款：主板1块，型号`LCKFB-TSPI3M-RK3576-4G-64G`、商品编号`C54110287`；原配散热风扇套件1套，型号`LCKFB-TSPI3M-COOLING-FAN-KIT`、商品编号`C55160086`。具体商品选项、金额、订单和原始截图集中维护在[采购清单](../../03_hardware/01_硬件清单.md)，无需重复购买。到货、排针装配、实际硬件版本及其他配件待核对。

供电资料存在两种表述：[官方规格书](../../04_references/04_datasheets/01_泰山派3M_RK3576_规格书.pdf)第3页将Power Type-C标为“5V-4A输入（仅供电）”，[快速指南](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/system-usage/)写5V输入、适配器峰值≥3A。采购按**5V/4A起，并另核相机、风扇与启动余量**；3A不是本车满载额定或板卡耗电上限。Type-C Power与规定5V排针不同时供电；上车由覆盖电池全电压范围的独立5V稳压支路供板，实测动态压降、纹波及温升。

规格书第3页的FAN接口仅支持5V。已购散热套件按[官方LCKFB-TSPI3M-COOLING-FAN-KIT说明](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/development-kit/cooling-fan-kit.html)核对，要求2026-07-06或之后的系统镜像；固定孔、外廓与质量仍需到货核实。

车载相机已购IMX415、30针MIPI、100度M12镜头，已付款、待发货；[订单与参考图纸](../../03_hardware/01_硬件清单.md#已购相机与商家图纸)已归档。先核固定孔、支架、排线含件，再逐针核对泰山派3M接口、供电、排线触点方向及镜像驱动；尚未板端出图，不能套用USB HOST或UVC采集步骤。RK与驱动经40针UART连接，先核对两端TTL电平，再按TX→RX2、RX←TX2、GND共地；两板分别供电，串口插头5V线悬空绝缘。接线与首轮命令见[底盘串口接线与首轮测试](./05_底盘串口接线与测试.md)。IMU等后续若接入，需要占用RK兼容总线并验证；当前不为此采购STM32。

规格书第1页已确认整板外形**85×57mm**，图示丝印V1.3；到货版本仍需登记。安装孔径/孔距、板厚、整板与散热套件净重未核，不从图片比例或商城98g毛重推算；接头、线缆与板底空间另核。电池、电机、驱动与重量预算仍按采购清单进一步核对，主板选型确认不等于整车配套参数已经闭合。UART必须完成可逐项比对的实际收发、状态回传与失联停车验收。

系统镜像与硬件资料从[官方资料下载中心](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/download-center.html)取得；本车尚未进行下载烧录、相机采集或UART实物验证。后续按实际使用的板版本、镜像及驱动记录结果，避免将教程示例或其他项目经验记为本车已通过。
