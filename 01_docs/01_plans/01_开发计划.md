# 开发计划

更新日期：2026-11-03。

当前顺序（2026-11-03讨论确认）：**摄像头出图 → 电脑持续查看画面和日志 → 前后、左右横移的定距离实测 → 车载识别与单枚推棋 → 连续多枚与策略优化**。供电、固定和停车条件随对应测试核对，采购与安装按实际需要并行推进。整机连接见[当前方案](../02_design/01_整机方案.md)。

电脑负责编辑，RK的Linux负责运行。已有的编辑、上传和板端运行流程直接复用；电机对应关系在运动测试中顺带复核，后续重点比较设定距离与实测位移。

当前已在板B完成地址修正、正式驱动识别、已有工具短时采图及有线传图，见[实机记录](../03_records/05_20261103_相机采集与电脑预览.md)。有线和Wi-Fi均可远程登录；Wi-Fi连续图传尚未验证。本次测试照片按用户要求清理，只保留进度、配置和必要的诊断记录。接下来完成正式采集程序，再扩展远程拍照和连续预览；分工与传输方式统一见[相机采集与电脑预览方案](../02_design/03_系统规划.md#camera-capture)。

#### 开发RK上的拍照采集功能

- [ ] 用C调用GStreamer（负责接收和处理图像的软件库），实现打开相机、设置采集参数、等待有效新帧、编码成JPEG照片、保存文件及关闭设备；源码归入 `02_programs/01_host/`，给出GCC编译和板端运行方法。
- [ ] 给程序提供明确的拍照调用入口，支持选择采集设备、分辨率和保存位置；每次返回照片路径、实际参数、帧号和采集时间，失败时返回具体原因。处理启动时画面尚未稳定、设备被占用、取帧超时和保存失败，避免误用上次照片。
- [ ] 上传到RK实际运行，用两次不同摆位的现场照片核对“发起一次拍照就保存一张新图”；这一项验收的是采集程序确实取得并保存图像，不能只检查编译通过。

#### 实现电脑控制拍照和取回照片

- [ ] 电脑通过已有SSH远程连接执行板端拍照命令；SSH用于远程执行命令，驱动与实际采集仍由RK完成。按同一次拍照的编号记录请求、采集结果和错误，电脑能知道本次照片是否已保存。
- [ ] 采集成功后，电脑按返回路径通过SCP取回文件；SCP是经远程连接复制文件的工具。打开照片核对现场内容，比较传输前后的文件指纹，确认内容一致；重复拍照时文件和结果各自对应，失败时明确提示。

#### 开发连续采集和电脑实时预览

- [ ] 把已通过的采集功能扩展为持续取帧，由同一个采集源提供拍照与预览；增加板内控制通道，让命令行把拍照、停止请求交给持续运行的采集程序，避免两个程序争用相机。
- [ ] 在RK增加HTTP预览服务，处理浏览器请求，并把连续JPEG图像组成MJPEG预览流返回电脑；实现启动、停止、重新连接及当前状态显示。拍照控制与日志先沿用SSH，照片取回沿用SCP，网页拍照按钮以后按需增加。
- [ ] 分别记录采集参数与预览参数，给预览缓存设上限，网络慢时及时显示新画面而不无限积压；预览可降低分辨率和帧率，保存的照片保留本次约定的采集分辨率。显示帧号、采集时间和画面过期状态，具体时间含义如实标明。
- [ ] 增加按需保存短视频的功能，记录视频采用的图像参数、格式和保存位置，停止保存后能取回电脑正常播放。

#### 板端与电脑联调验收

- [ ] 在电脑发起拍照、取回原图，同时预览并移动真实棋子，核对命令、保存照片和连续画面是否对应；检查清晰度、曝光、画面方向，保存原始照片、短视频与实际参数。正式装车后另核最终机位、遮挡和振动。
- [ ] 首轮按连续预览10分钟检查卡顿与延迟，再测试停止重开、断网重连和RK重启后的恢复；记录实际结果及恢复方法，手动启动与自动启动分别登记。

完成标准：RK上的驱动与采集程序实际运行通过；电脑能控制一次拍照、取回并打开对应的新照片，也能连续预览现场变化、查看真实日志。保存可复核的原始照片、短视频、参数及恢复步骤；驱动可用、采集功能通过、网络传输通过和正式装车验证分别登记。

下一项实际工作：基于已经出图的采集入口，编写可重复调用的C拍照程序，再接入电脑连续预览。两次短时采集启动时仍有MIPI接收错误标志和消隐时间不足的提示，需在连续采集时跟进图像及稳定性；目前不认定长时间运行通过。配置、排查和验收统一更新[同一相机记录](../03_records/05_20261103_相机采集与电脑预览.md)。本次临时测试照片不保留；后续正式标定、识别输入按用途归档。网络沿用现有配置，相机服务避开已有业务使用的TCP 5000端口。

### 2. 电脑持续查看画面、识别过程和运行日志

目标：调试时能回答“小车看到了什么、程序怎样判断、准备做什么、实际执行怎样”。优先通过Wi-Fi传画面与数据，复用已有远程终端查看日志、启动和停止程序；具体连接按当前RK系统核实。蓝牙按需要补充少量状态或文字数据，不作为首轮连续画面的主链路。

本节在第1步的原始画面与采集日志基础上扩展，随识别和运动功能逐项接入，不把全部调试界面作为相机出图的前置条件。

- [ ] 复用第1步已通过的预览和日志查看方法，整理成固定的启动、停止、重连和取回测试资料的操作入口。
- [ ] 逐项接入实际算法输出：检测框、身份或“未知”、位置估计、当前目标、运行阶段及阶段切换原因；尚未实现的能力不显示为真实结果。
- [ ] 接入运动调试数据：设定动作/距离、实际发送命令、轮速和编码器原始反馈、累计距离、停车原因及异常提示；不能只显示成功/失败或数量汇总。
- [ ] 画面、识别结果和运动日志带可对应的时间或帧号；每次测试记录程序版本、参数和模型，能找到当时的原图、指令和反馈。接收时间与实际采集时间分别说明，不假称精确同步。
- [ ] 显示连接中断和画面过期，限制预览与日志缓存；网络慢或电脑接收慢时，调试显示不阻塞RK运动控制，并在RK保留必要原始数据。

完成标准：电脑能同时持续查看原始画面和真实日志，并能保存、取回同一次测试的数据；后续每接入一项算法或运动功能，就增加对应显示。当前未接入算法时，先验收画面和日志；识别显示随算法单独验收。

本阶段预期成果：在电脑前能够看见相机画面、查看程序输出，并为下一步完整观察一次定距离运动测试做好准备；目前仍待实施和验收。

## 未完成即将执行

### 3. 前后与横向定距离运动 {#2-电脑单轮调试泰山派40针串口直连驱动与首轮测试}

目标：分别设置前进、后退、左横移、右横移的距离，用地面实测核对小车实际移动，找出换算、打滑、跑偏和停车造成的误差。电机基础对应关系随测试复核，不重复安排一轮已完成的入门调试。

启动条件：供电和安装满足本次动作要求，电脑能查看运动日志；落地前确认正常停车与通信中断等异常停车条件，独立失联保护仍按[接线与测试](../02_design/05_底盘串口接线与测试.md#6-异常测试与落地条件)核验。

- [ ] 盘点本车已有运动代码并复用，补齐四轮速度换算、距离累计、减速与停车；核实际RK串口接线、轮序/方向及原始反馈，发现不符时针对性排查。已有编辑运行流程不等于本车运动程序已通过。
- [ ] 将“走指定距离”落实到RK控制：驱动主要接收轮速，RK根据反馈累计运动并决定减速、停车；若先用“速度×时间”粗测，明确记录方法，不算反馈定距离控制已完成。
- [ ] 在可测量的场地上标起点，以车体同一参考点测停车后的位移；前进、后退、左横移、右横移分别测试，距离先短后长，记录速度、载荷、地面和供电条件。
- [ ] 每次同时保存设定距离、编码器估计距离、地面实测距离及误差，另记侧向偏移、朝向变化和停车后位置；保留实际指令、反馈及视频/测量照片。
- [ ] 同一方向与条件重复测试，再比较不同距离、速度下的结果；测试前明确重复次数，允许误差按真实场地、车体和推送余量确定，不凭一次成功认定稳定。
- [ ] 相机预览与运动同时运行，检查指令/反馈间隔和停车是否受影响，以及车载供电是否掉压、重启；基础动作稳定后再扩展旋转、组合动作和带载测试。

完成标准：四个方向均有可重复核对的“设定距离—编码器估计—实测位移”数据及跑偏、朝向和停车结果；完成本轮约定的误差与停车验收。轮子转了、反馈数值变化或程序正常退出，均不能代替车身位移验证。

具体操作和实际结果继续更新[同一底盘调试记录](../03_records/04_20261030_底盘串口调试.md)。

### 4. 车载识别与单枚推棋

相机出图后即可采集实拍、推进识别，与底盘实测并行；自主运动需满足上述供电、安装和停车条件。

- [ ] 采集真实棋子图片，完成相机标定，用独立实测位置核对图像与实际位置的对应；原始输入与人工答案分开保存。
- [ ] 分别验证自动找棋子、相对位置、身份和字色，记录漏检、误识、拒识及处理耗时，并接入电脑调试显示。
- [ ] 用固定摆位先验证机械推送和释放，再串起单枚棋子的观察、识别、接近、对准、推送、到位确认和失败退出。约定场地、起点和目标条件，保存成功与失败的完整视频；固定动作试推、人工辅助与运行中无人辅助分别说明，不能互相代替验收。

完成标准：实车能够完成一枚棋子的识别与推送，并能确认棋子实际到达目标区；单项程序运行成功不算整车通过。
